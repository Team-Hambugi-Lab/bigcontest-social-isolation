# LLM 역할과 안전장치 — 2026-10-26

> 서비스 플로우 [README.md](README.md) v1.5의 단계(0\~5)에서 LLM이 맡는 범위다. 모두 **[제안]**이고, 아래에서 "N절"은 README의 절 번호다.

원칙은 4절과 같다. **판단은 규칙이 하고, LLM은 말을 만든다.** 티어, 위기 여부, 후보 통과, 기관 목록은 LLM 출력으로 정하지 않는다. LLM이 멈추거나 틀린 말을 해도 판단 결과는 그대로이고, 고정 문구로 같은 흐름을 이어 갈 수 있어야 한다.

## 단계별로 하는 일과 하지 않는 일

| 단계 | LLM이 하는 일 | LLM이 하지 않는 일 (누가 하나) |
|---|---|---|
| 0 온보딩 | 고정 문항을 대화체로 묻는다. 자유 응답이 오면 맞을 것 같은 선택지를 보여 주고 본인이 고르게 한다 | 위험 특징을 정하지 않는다 (본인이 고른 선택지 → 규칙) |
| 1 분류 | 없음 | 특징 코드 부여 (위험 특징 사전 규칙) |
| 2 관찰 | 체크인 인사와 질문을 만든다. 자유 응답을 요약해 담당자 기록에 붙인다 (원문도 함께 남긴다) | 무응답·이동 수치 계산, 기준선 계산 (규칙) |
| 3 탐지 | 없음 | 티어 결정 (2-2절 결정표), 위기 여부 (아래 안전장치 2) |
| 4 추천 | 문항표의 `QUESTION`을 말투만 바꿔 묻는다. 통과한 기관·사업을 DB 필드로 설명한다 | `PASS_IF` 판정 (본인이 고른 선택지), 후보 순서 (`PRIORITY`), 기관 거르기 (2-3절 4) |
| 5 후속 | 이용 여부와 도움 정도를 묻는다 | 이용 기록 (기관·사업 ID로 저장) |
| 지역 층 | 쓰지 않는다 | 관찰 우선 지역 (2-1절 규칙) |

## LLM에 넘기는 입력

| 넘긴다 | 넘기지 않는다 |
|---|---|
| 지금 묻는 문항과 선택지, 직전 몇 턴의 대화 | 이름, 연락처, 생년월일 같은 식별 정보 (가명 ID만 쓴다) |
| 사용자의 특징 코드와 연령대 (말투와 설명을 맞추는 데 필요한 만큼) | 행정동보다 자세한 위치, 이동·체류 원자료 |
| 통과한 후보 기관·사업의 DB 필드 (이름, 주소, 서비스, 기준일) | 티어 이력 전체, 담당자 메모, 다른 사용자의 정보 |

- 시연에는 페르소나 합성 데이터만 넣는다 (6절). 실제 개인 응답은 넣지 않는다.
- 대화 기록을 얼마나 보관할지, 모델 쪽에 기록이 남지 않게 할지는 실제 운영 전에 정한다 **[미결정]**.

## 모델 선택 [미결정]

어떤 모델을 쓸지는 정하지 않았다. 고를 때 볼 조건은 다음과 같다.

- 한국어 대화가 자연스럽고, 고령 사용자에게 쉬운 말로 바꿔 말할 수 있는가
- 출력을 정해진 형식(선택지 ID, 기관 ID)으로 낼 수 있어 규칙으로 검사할 수 있는가
- 실제 운영에서 개인정보를 처리할 수 있는 조건(처리 위치, 기록 보관, 학습 사용 여부)을 만족하는가. 시연은 합성 데이터라 이 조건이 없어도 되지만, 운영 안에는 따로 적는다

## 잘못된 답에 대한 안전장치

1. **문항표 밖에서 판정하지 않는다.** 조건 확인의 통과 여부는 본인이 고른 선택지로 정한다. LLM이 "조건을 충족한 것 같다"고 말해도 통과로 처리하지 않는다. 선택지로 확인되지 않으면 보류다 (2-3절 3).
2. **위기 확인은 LLM보다 먼저 한다.** 모든 사용자 입력은 LLM에 가기 전에 위기 표현 규칙(자살·자해 관련 어휘 목록)으로 먼저 검사한다. 걸리면 LLM 응답을 만들지 않고 고정 문구로 `CRISIS_LINE`을 안내하며 사람에게 이관한다. LLM은 위기 의심을 올릴 수는 있지만 내릴 수는 없다. 규칙에 걸린 입력을 LLM이 "위기가 아니다"라고 판단해도 이관은 그대로 간다.
3. **없는 기관을 만들지 않는다.** 기관·사업 안내에는 넘겨받은 후보의 ID만 쓴다. 출력에 들어간 ID가 후보 목록에 있는지 검사하고, 없거나 전화번호·주소가 DB 값과 다르면 그 문장을 버리고 DB 필드를 그대로 보여 준다.
4. **진단하지 않는다.** 병명, 약, 치료 효과를 말하지 않는다. 수치는 `SUPPORT_NEED_PCT` 같은 DB 값만 쓰고 새 숫자를 만들지 않는다 (2-4절 d).
5. **실패하면 고정 문구로 간다.** 응답이 없거나 형식 검사를 통과하지 못하면 문항표 원문과 DB 필드를 그대로 보여 준다. 흐름은 멈추지 않는다.
6. **시연 전에 금지 출력을 시험한다.** [`scenarios.md`](scenarios.md)의 대화에 위기 표현, 모호한 조건 응답, 없는 기관 요청을 섞어 위 1\~5가 지켜지는지 확인한다.
