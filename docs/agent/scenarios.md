# 에이전트 활용 시나리오 — 2026-10-24

> 서비스 플로우 [README.md](README.md)의 규칙(2-2 티어, 2-3 추천 절차, 2-4 운영 규칙 제안)을 그대로 적용한 페르소나 예시 2개다. 사람과 대화 내용은 가상이고, 기관·지원사업은 `institutions.csv`, `support_programs.csv`(2026-10-24 기준)의 실제 행이다. 티어 기준 숫자는 시연용 가정이다.

## 합성 방법

대회 규정상 페르소나 합성 데이터는 생성 방식을 밝히고 실제 관측값과 구분해야 한다. 두 사례는 통계 모델로 생성하지 않았다. **실제 통계를 근거로 사람이 직접 설계한 사례**다.

| 구분 | 만든 방법 | 성격 |
|---|---|---|
| 인물 설정 (나이, 지역, 가구 형태) | 대회 대상 지역(강남구, 춘천시)과 분석 대상 연령층(청년, 60대 이상)에서 한 명씩 정했다. 춘천은 행정동까지 정했는데, 효자2동은 "둘 다 해당" 집계구가 춘천에서 가장 많은 동이라 골랐다 | 가상 |
| 위험 특징 조합 | `risk_feature_dictionary.csv`에서 골랐다. 청년은 보건복지부 2023 실태조사에서 고립·은둔 청년의 해당 비율이 40\~70%대인 특징 4개, 고령은 고령 근거가 있는 특징 2개(독거, 교류 드묾)다 | 가상 (근거는 실제 통계) |
| 응답과 대화 문장 | 직접 썼다. LLM으로 생성하거나 실행한 결과가 아니다 | 가상 |
| 관찰 수치 (주간 외출 4일 → 2일 등) | 티어 상향·하향 규칙을 보여 주려고 정했다 | 가상 (시연용 가정) |
| 기관, 지원사업, 효자2동 집계구 수 | `institutions.csv`, `support_programs.csv`, `h4_exposure_combined_dong.csv`의 실제 행이다 | 실제 데이터 |

한계:

- 사례 2개는 해당 연령층을 대표하지 않는다. 특징이 어떻게 함께 나타나는지(동시 발생 분포)를 흉내 내지 않았다.
- 응답과 관찰 수치는 규칙의 동작을 보여 주기 위한 값이라, 탐지·추천 성능의 근거가 되지 않는다.
- 발표자료에서는 인물·대화 부분에 "가상 인물·예시 대화(합성)"를, 기관·사업 부분에 "실제 기관 데이터"를 표시한다.

## 두 시나리오의 차이

| | A. 청년 (서울 강남구) | B. 고령 (강원 춘천시) |
|---|---|---|
| 시작 티어 | 2 연계 권유 (범주 4개) | 1 정보 안내 (범주 2개) |
| 지역 신호 | 쓰지 않음 (60대 이상에만 적용) | 관찰 우선 지역이면 관찰 주기만 짧게 |
| 보여 주는 규칙 | 후보 불충족 → 다음 후보, 같은 태그 합치기, 보류, 태그는 맞지만 실제 서비스가 다른 경우 | 독거 단정 금지, 운영 종료 기관 제외, 티어 상향, 자원 공백 기록, 티어 하향 |

## A. 청년 — 강남구 28세, 1년 넘게 집에 머묾

**0 온보딩**

- 거주 시군구 강남구, 연령대 20대. 체크인 알림·기관 연계 시 정보 제공에 동의, 이동 요약 수집은 동의하지 않음.
- 자살·자해 생각 문항: 없음 → 위기 경로 아님.

**1 분류 → 3 티어**

| 특징 코드 | 범주 | 근거 응답 |
|---|---|---|
| `OUT_LONG_DURATION` | OUT | 1년 넘게 거의 집에만 있었다 |
| `REL_LONELY` | REL | 외로움을 자주 느낀다 |
| `BODY_SLEEP` | BODY | 밤낮이 바뀌었다 |
| `MIND_SOCIAL_ANXIETY` | MIND | 사람 만나는 게 두렵다 |

해당 범주 4개 → **티어 2 (연계 권유)**, 관찰 주기 주 1회. 청년이라 지역 활동 신호는 쓰지 않는다. 기준선은 4주 뒤에 생기므로 그 전에는 악화 판단을 하지 않는다.

**4 추천 후보 확인** (`PRIORITY` 순, 확인 문항은 [`note_check_questions.csv`](note_check_questions.csv))

| 특징 | 후보 | 본인 답 | 처리 |
|---|---|---|---|
| `MIND_SOCIAL_ANXIETY` | `MENTAL_CARE` (1) | 상담 받아 보고 싶다 | 통과 |
| `OUT_LONG_DURATION` | `ISOLATION_CARE` (1) | 상담 받아 볼 생각 있다 | 통과 |
| `REL_LONELY` | `SOCIAL_PART` (1) | 아직 사람 많은 곳은 부담된다 | 불충족 → 다음 후보 |
| `REL_LONELY` | `MENTAL_CARE` (2) | 상담 받아 보고 싶다 | 통과. 이미 나온 태그라 한 번만 안내하고 근거 특징에 `REL_LONELY`를 더한다 |
| `BODY_SLEEP` | `HEALTH_MGMT` (1) | 잘 모르겠다 | **보류** ("확인 대기"). 다음 체크인에서 한 번 더 묻는다 |

표시 순서는 본인이 "가장 힘든 것"으로 고른 `MIND_SOCIAL_ANXIETY`를 먼저 둔다 (2-4절 e).

**기관 필터** (강남구, 대상 연령 `ALL`, 운영 상태)

| 태그 | 통과 기관 | 비고 |
|---|---|---|
| `MENTAL_CARE` | 서울강남구정신건강복지센터 (`INST010894`) | 좌표 없음 → 주소만 보이고 "가까운 곳"이라고 하지 않는다. 같은 태그의 강남구중독관리통합지원센터(`INST010939`)는 실제 서비스가 중독 상담이라 제외한다 (중독은 본인 요청 경로) |
| `ISOLATION_CARE` | 강남종합사회복지관 (`INST010916`), 태화기독교사회복지관 (`INST010921`) | 좌표 있음. 행정동을 받았으면 가까운 순으로 보인다 (2-4절 b) |

**지원사업** — 강남구 사업은 0건이다. 서울 전체 사업(`SGG` 빈칸) 중 모집 중이고 청년 대상인 2건이 태그로 걸린다.

| 사업 | 태그 일치 | 처리 |
|---|---|---|
| 서울 둘레길 걷기 프로그램 (`SIHSC059`, 11/30 마감) | `ISOLATION_CARE`, `MENTAL_CARE` | 안내한다. 단체 야외 활동이라 "부담되면 나중에 해도 된다"고 덧붙인다 |
| 청년동행센터 금융복지 출장상담 (`SIHSC075`, 12/22 마감) | `MENTAL_CARE` | 내용이 부채 상담이고 ECON 특징이 없어 실제 서비스 확인에서 제외한다 |

태그가 맞아도 실제 내용이 다를 수 있다는 기관 매핑 조건을 보여 주는 예다.

**연계 (티어 2)** — 후보 3개(정신건강복지센터, 사회복지관 2곳, 둘레길 사업)를 권하고, 본인이 사회복지관 연계에 동의해 기관에 연계를 요청한다.

**5 후속 (2주 뒤)**

- 강남종합사회복지관 상담 1회 이용 → 기관 ID로 기록.
- 정신건강복지센터는 "전화하기가 부담돼서" 이용하지 않음 → 추천 조건 3(연계했지만 이용 안 함). 거절이 아니므로 다음 체크인에서 이용 방법(방문 예약, 동행 등)을 다시 묻는다.
- 보류였던 `BODY_SLEEP`을 다시 물었더니 상담을 원함 → `HEALTH_MGMT` 통과, 세곡동·수서동 건강증진센터 안내.
- 새 특징 없음, 악화 판단은 기준선(4주) 이후 → 티어 2 유지.

## B. 고령 — 춘천시 72세, 혼자 사는 남성

**0 온보딩**

- 거주 시군구 춘천시, 행정동 효자2동(선택 입력), 연령대 70대. 체크인 알림, 이동 요약, 기관 연계 정보 제공에 동의.
- 자살·자해 생각 문항: 없음.

**1 분류 → 3 티어**

| 특징 코드 | 범주 | 근거 응답 |
|---|---|---|
| `SOLO_LIVING` | SOLO | 혼자 산다. "아플 때 걱정된다"고 답해 어려움으로 확인됨 → 센다 (독거 자체만으로는 세지 않는다) |
| `REL_LOW_CONTACT` | REL | 사람을 만나는 날이 일주일에 하루도 안 된다 |

해당 범주 2개 → **티어 1 (정보 안내)**. 효자2동은 관찰 우선 지역이라 관찰 주기만 격주 → 주 1회로 짧아지고 티어는 그대로다.

효자2동 근거 (`h4_exposure_combined_dong.csv`, 60대 이상, 지수 v3.3): 집계구 33개 중 노출 지수 관찰 후보이면서 활동 신호인 "둘 다 해당" 집계구가 10개로 춘천 25개 읍면동 중 가장 많다 (다음은 석사동·신사우동 3개). 활동 신호 집계구 14개, 관찰 후보 21개, 둘 다 보류 2개다. 네 구분은 집계구 단위이므로, 행정동을 관찰 우선 지역으로 부르는 것은 그 안에 "둘 다 해당" 집계구가 있다는 뜻이다.

**4 추천 후보 확인**

| 특징 | 후보 | 본인 답 | 처리 |
|---|---|---|---|
| `SOLO_LIVING` | `CARE_CHECK` (1) | 아직은 괜찮다 | 불충족 → 다음 후보 |
| `SOLO_LIVING` | `SOCIAL_PART` (2) | 사람들 만나고 싶다 | 통과 |
| `REL_LOW_CONTACT` | `SOCIAL_PART` (1) | 같은 답 | 통과. 같은 태그라 한 번만 안내 |

`CARE_CHECK`를 원했더라도 춘천의 후보 7곳 중 노인맞춤돌봄 수행기관 4곳은 `VALID_UNTIL`(2025-12-31)이 지나 "운영 여부 확인 필요"로 빠지고 사회복지관 3곳만 남는다.

**기관 필터** — `SOCIAL_PART` 춘천 364곳 중 대상 연령(`ALL`·`60+`·`65+`)과 운영 상태를 통과한 361곳(경로당 354, 노인복지관 4 등). 좌표가 있는 곳은 효자2동 기준 가까운 순으로 3곳을 보인다. **지원사업** — 60건이 모두 서울 사업이라 춘천에는 없다. "지원사업 없음"으로 표시한다.

**연계 (티어 1)** — 노인복지관·경로당 정보를 알려 주고 본인이 스스로 이용한다.

**2 관찰 → 3 악화 (6\~7주차)**

- 첫 4주 기준선: 주간 외출 4일.
- 6\~7주차 2주 연속 주간 외출 2일 이하(기준선 절반 이하) → **티어 1 → 2**.
- 티어 2인데 연계 기록이 없음 → 추천 조건 2로 4단계를 다시 돈다.

**4 재확인**

- `SOCIAL_PART`를 이용하지 않은 이유: "혼자 가기 어색하다". 티어 2라 노인복지관에 연계를 요청하는 데 동의를 받는다.
- `REL_LOW_CONTACT`의 2순위 `ISOLATION_CARE`는 춘천에 0곳 → 이 후보는 "지역 내 후보 없음"으로 기록하고 자원 공백 집계(춘천 × `ISOLATION_CARE`)에 넣는다.

**5 후속 (2주 뒤)**

- 노인복지관 프로그램 1회 참여 → 기관 ID로 기록.
- 이후 체크인 2회 연속 외출이 기준선 수준으로 회복, 새 특징 없음 → **티어 2 → 1**.
