## 설계 결정

### 1. 연령 구간 맞추기

남녀 합계 SGIS 5세 단위 칸 두 개를 SK 10세 구간 하나에 맞춘다. SK 유동은 남녀를 더해서 쓴다.

| SK 구간 | SGIS 거주 인구 |
|------|------|
| 10대 | `003` + `004` |
| 20대 | `005` + `006` |
| 30대 | `007` + `008` |
| 40대 | `009` + `010` |
| 50대 | `011` + `012` |
| 60대 이상 | `to_in_001` − (`001`~`012` 합) |

- 0~9세(`001`, `002`)는 SK에 짝이 없어서 거주 인구 모델에 쓰지 않는다. 다만 60대 이상을 빼기로 계산할 때는 들어간다.
- **60대 이상을 빼기로 구하는 이유:** 고연령일수록 비공개 칸이 많다(85~89세 55%, 90~94세 89%). 그래서 직접 더하면 고령 인구가 많은 집계구일수록 작게 잡힌다.
- **성별을 나누지 않는 이유:** 성별 칸은 비공개 비율이 훨씬 높아서 고령층 보류가 크게 늘어난다. 성별로 나눈 버전은 민감도 확인에서만 돌린다.

### 2. 비공개 칸(`source_na`)과 기록 없음(`no_record`) 처리

- `source_na`: 1~4명이다. 점추정은 2.5명으로 두고, 하한(1명)과 상한(4명)을 함께 계산한다.
- `no_record`: 0명으로 본다. 총인구(`to_in_001`)가 0이면 거주 인구가 없는 집계구로 보고 보류한다(30개).
  - 처음에는 "0~59세 12칸이 모두 비면 거주 인구 없음"으로 정했지만, 이 규칙은 총인구 388명인 요양시설 집계구(`11230760040002`)를 잘못 보류한다. 총인구 기준으로 바꿨다(Task 1, 2026-10-17).
- 각 연령대 거주 인구에 `RESIDENT_LOW`, `RESIDENT_HIGH`, `N_MASKED_CELLS`를 남긴다.
  - 60대 이상은 빼기로 계산하므로 방향이 반대다. 하한 = 총인구 − (0~59세 상한 합), 상한 = 총인구 − (0~59세 하한 합).
  - 총인구가 적고 비공개 칸이 많은 집계구에서는 빼기 결과(점추정·하한)가 **음수**가 될 수 있다. 0으로 자르고 `RESIDENT_CLIPPED = True`로 표시한다. 해당 집계구 수는 Task 1에서 센다.

### 3. 기대값 모델

연령대별로 따로 적합한다. 연령대마다 계수를 따로 두는 것과 같다.

```
log(FLOW_a) ~ log(RESIDENT_a) + log1p(EMPLOYEES) + log(FLOW_OTHER_a) + C(STD_YM) + C(REGION)
```

| 항목 | 정의 |
|------|------|
| `FLOW_a` | 그 연령대 SK 일평균 유동(남녀 합) |
| `RESIDENT_a` | 1·2절의 점추정 |
| `EMPLOYEES` | 총종사자수. 0인 집계구가 있어서 `log1p`를 쓴다 |
| `FLOW_OTHER_a` | 그 연령대를 **뺀** 나머지 연령대 유동 합. 전체 유동 규모를 통제한다. 대상 연령대를 포함하면 좌변이 우변에 기계적으로 들어간다 |
| `STD_YM`, `REGION` | 월 효과, 지역(강남·춘천) 효과 |

- **적합 대상:** 보류 사유가 없는 집계구-월만 쓴다. 잔차는 계산할 수 있는 모든 행에 대해 구하되, 보류 행은 `JUDGEMENT_STATUS = held`로 남긴다.
- **잔차를 계산할 수 없는 행:** `RESIDENT_a ≤ 0`이면 `log`가 정의되지 않는다(`log(0) = −∞`). 이 행은 잔차를 결측으로 두고 보류 사유 `zero_resident_band`를 붙인다. `FLOW_a`와 `FLOW_OTHER_a`는 0값이 없음을 확인했지만(20행), 구현에서도 같은 처리를 한다.
- **구현:** `statsmodels`는 기본 의존성이 아니다. `sklearn.linear_model.LinearRegression`과 `pd.get_dummies`로 적합한다. 계수 표준오차는 판정에 쓰지 않으므로 보고서에는 집계구 단위 부트스트랩 구간만 붙인다(`random_state=42`).
- **진단:** 연령대별 R², 잔차 분포, 지역별 잔차 평균, 적합값 대비 잔차 그림을 확인한다.
- **규모 교란 진단:** 연령대 거주 인구 5분위별로 신호율과 `MEAN_RESID`를 표로 낸다. 신호가 거주 인구가 작은 분위로 단조롭게 몰리면, 잔차가 "활동 저하"가 아니라 "작은 집계구"를 찾고 있는 것이다. 잔차와 `log(RESIDENT_a)`의 상관은 적합에 쓴 행에서는 OLS 성질상 0이므로 이 확인에 쓰지 않는다.

### 4. 잔차와 지속성 판정

- `RESID = log(FLOW_a) − 예측값`이다. 음수이면 기대보다 낮은 것이다.
- `N_LOW_MONTHS`: 6개월 중 `RESID < 0`인 달 수.
- **신호:** `N_LOW_MONTHS ≥ K` 이고 `MEAN_RESID < 0`이면 신호로 본다. 기본 `K = 4`.
- **보류 행:** `SIGNAL`과 `N_LOW_MONTHS`를 `False`나 0이 아니라 **결측**으로 둔다. `MEAN_RESID`는 계산할 수 있으면 참고값으로 남긴다. "판단할 수 없음"이 "신호 없음"으로 읽히지 않게 하려는 것이다.
- **해석 주의:** 거주 인구는 2024년 값 하나로 고정되어 있다. 그래서 여러 달 잔차가 낮게 이어지는 것은 대부분 집계구의 **고정된 수준 차이**이고, 시간이 지나며 활동이 **줄어드는 추세가 아니다.** 보고서에 "기대보다 낮은 상태가 지속된다"로 쓰고 "감소한다"로 쓰지 않는다. 월별 잔차의 집계구 내 상관(ICC)을 함께 보고한다.

### 5. 판단 보류(`HOLD_REASON`)

"이 집계구는 잔차를 믿기 어려우니 신호 판정을 하지 않는다"고 표시하는 규칙이다. 데이터가 부족하거나 모델이 전제하는 상황(주민 활동이 유동의 주된 부분)과 다른 집계구를 거른다.

보류 사유가 여러 개면 `;`로 이어 붙인다. 보류 행도 결과에서 빼지 않는다.

| 사유 | 조건 | 적용 연령대 |
|------|------|------|
| `no_sk` | `HAS_SK_POINTS` 거짓 | 전체 |
| `no_resident` | 총인구 0 (30개) | 전체 |
| `institution` | 총인구가 가구원 수 합(`to_ga_001 × to_ga_002`)의 1.5배를 넘거나 가구 0. 주민의 1/3 이상이 요양시설·기숙사·군부대 같은 집단시설 인구다 (15개) | 전체 |
| `small_sample` | `is_small_sample` | 전체 |
| `zero_resident_band` | 그 연령대 거주 인구 점추정 ≤ 0. 잔차를 계산할 수 없다(3절) | 해당 연령대 |
| `small_resident_band` | 그 연령대 거주 인구 점추정 < `MIN_RESIDENT` (기본 20명) | 해당 연령대 |
| `extreme_visitor` | #12 결론에서 유동 패턴이 꾸준히 극단적이었던 춘천 집계구 11개 | 전체 |
| `work_area` | 종사자 / 총인구 비율이 **지역(강남·춘천) 안에서** 상위 `WORK_Q`. 기본은 상위 5%, 20~30대는 상위 10% | 연령대별 |
| `no_exposure_score` | 노출 지수 결합 단계에서 노출 점수가 없는 집계구 | 결합 단계 |

- `extreme_visitor` 목록은 #12 코멘트(2026-10-15)의 표를 상수로 옮기고 출처를 주석에 남긴다.
- `institution`을 보류하는 이유: 집단시설 거주자는 이동이 제한되므로 잔차가 낮게 나오지만, 지역사회 고립과는 다른 현상이다. Task 1에서 추가했다.
- `work_area` 분위를 지역별로 세는 이유: 강남과 춘천을 합쳐서 세면 상위권이 거의 강남 업무지로 채워져 춘천의 업무지가 걸러지지 않는다. 합쳐서 세는 방식은 민감도에서 비교한다. 총인구 0인 집계구는 비율이 정의되지 않지만 이미 `no_resident`로 보류된다.
- `no_exposure_score`는 결합 함수에서 붙인다. 이번 산출물은 1,698개 집계구를 모두 포함하므로, 노출 점수가 없는 집계구가 결합 과정에서 조용히 빠지지 않는다.

### 6. 행정동 집계

집계구 단위 결과(`h4_signal_oa.csv`)를 행정동 × 연령대로 모은다. 행정동 47개 × 6연령대 = 282행이다.
- 282행은 모든 행정동에 집계구가 하나 이상 있어야 성립한다. `master_analysis.csv`에서 확인했다(2026-10-17): `ADM_CD` 결측 0, 집계구마다 행정동이 하나, 동별 집계구 수는 최소 2개·중앙값 34개·최대 94개다.
- 집계구가 2개뿐인 동도 있으므로, 이런 동의 `SIGNAL_RATE`는 0·0.5·1처럼 거칠게 나온다. `N_JUDGED`와 함께 읽어야 한다.

| 열 | 뜻 | 계산 |
|------|------|------|
| `N_OA` | 그 행정동에 속한 집계구 수 | 집계구 수. 보류 여부와 관계없이 센다 |
| `N_JUDGED` | 신호 판정을 한 집계구 수 | `JUDGEMENT_STATUS`가 `held`가 아닌 집계구 수 |
| `N_HELD` | 판단 보류한 집계구 수 | `held`인 집계구 수. `N_OA = N_JUDGED + N_HELD` |
| `N_SIGNAL` | 활동 저하 신호가 나온 집계구 수 | 판정한 집계구 중 `SIGNAL`이 참인 수 |
| `SIGNAL_RATE` | 판정한 집계구 중 신호 비율 | `N_SIGNAL / N_JUDGED`. `N_JUDGED = 0`이면 0이 아니라 결측으로 둔다 |
| `RESIDENT` | 그 연령대 거주 인구 합 | 집계구별 `RESIDENT_a` 점추정의 합. 보류 집계구도 포함한다 |
| `DONG_POOLED_RESID` | 동 전체의 기대 대비 유동 | 동 안의 모든 집계구(보류 포함, 잔차 계산 불가 행 제외)의 실제 유동 합과 기대 유동 합으로 `log(Σ실제 / Σ기대)`를 6개월 평균한 값 |

- **분모를 `N_OA`가 아니라 `N_JUDGED`로 두는 이유:** 보류 집계구는 신호가 "없는" 것이 아니라 "판단할 수 없는" 것이다. `N_OA`로 나누면 보류가 많은 동일수록 신호 비율이 낮게 나온다.
- **`N_JUDGED = 0`일 때 결측으로 두는 이유:** 0으로 두면 "판정했더니 신호가 없다"로 읽힌다. 실제로는 판정할 집계구가 없었던 것이다.
- **`N_HELD`를 함께 내는 이유:** `SIGNAL_RATE`가 같아도 판정한 집계구가 2개인 동과 30개인 동은 믿을 수 있는 정도가 다르다. 결과를 쓰는 사람이 이 비율이 몇 개 집계구에서 나온 것인지 볼 수 있어야 한다.
- **`DONG_POOLED_RESID`를 함께 내는 이유:** `SIGNAL_RATE`는 판정한 집계구만 쓰므로, 해당 연령 거주 인구가 적어 보류된 집계구가 동 지표에서 체계적으로 빠진다. 작은 값을 버리지 않고 동 단위로 합산하면 이 집계구들도 동 지표에 반영된다. 기대값은 보류 행을 뺀 모델로 만든 것이라, 보류 행이 많은 동에서는 참고값으로 읽는다.

### 7. 신한카드 시군구 맥락

`card_cohort.prepare_card(2)`를 재사용해 지역 × 성별 × 연령대 표를 만든다. 금액·건수는 6개월(2025-07~12)을 **합친 뒤** 비중을 계산한다. 월별 값은 `cohort_panel()` 결과에 이미 있으므로 따로 내지 않는다.
- 업종 그룹 비중: 대면 관계 소비(`SOCIAL_RY`) 비중과 미분류 제외 금액 비중.
- 외지 고객 비중: 춘천만 근사값으로 낸다. 강남은 결측으로 두고 이유를 열 정의서에 적는다.

이 표는 신호 판정에 쓰지 않는 맥락 자료다.

## 민감도 확인

기본 설정 대비 신호 집계구 집합의 겹침(Jaccard)과 `MEAN_RESID` 순위상관(Spearman)을 연령대별로 보고한다.

| 변형 | 바꾸는 것 |
|------|------|
| K | 3, 5, 6 |
| M1 | 지역 효과 대신 행정동 고정효과. 잔차가 동마다 평균 0이 되어 "같은 동 안에서 낮은 집계구"를 보는 다른 질문이 된다. **집계구 단위 Jaccard·Spearman만 보고, 동 단위 `SIGNAL_RATE` 비교에는 쓰지 않는다** |
| M2 | `FLOW_OTHER_a` 대신 전체 유동(대상 연령 포함) |
| M3 | 성별로 나눈 연령대(남/여 따로 적합) |
| M4 | 비공개 칸을 하한·상한으로 바꿔 다시 계산 |
| M5 | 60대 이상을 직접 합으로 계산 |
| 보류 | `work_area` 분위 5%/10%/20%, `work_area` 분위를 지역 합산으로 계산, `MIN_RESIDENT` 10/20/50 |

**판단 기준(잠정):** 60대 이상과 20~30대에서 K=3~5 및 M1·M2·M4의 Jaccard가 0.6 이상이면 "결과가 크게 달라지지 않는다"로 본다. 기준에 못 미치면 신호를 하나로 정하지 않고 범위로 보고한다.

2. ~~`MIN_RESIDENT = 20`은 잠정값이다.~~ Task 1에서 20을 유지하기로 했다. 20~60대 이상에서 21~70개 집계구만 보류되고, 50으로 올리면 20대 877개·30대 700개가 보류된다(보고서 1.4절).
3. 신호 기준(`K=4`, `RESID < 0`)은 "조금이라도 낮은 달"을 센다. 잔차 크기 기준(예: `RESID < −0.1`)을 더할지는 Task 1의 잔차 분포를 보고 정한다.

4. 노출 × 활동 신호로 우선 대상 행정동을 고르는 기준은 정하지 않았다. Task 7 결과 파일을 만든 뒤 팀과 논의한다.
